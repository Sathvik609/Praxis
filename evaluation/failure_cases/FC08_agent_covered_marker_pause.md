# FC08 — Agent left the patient paused after a covered marker

**Source:** agent re-check, 21 Oct (synthetic OpenCV frames, real Claude Sonnet 5.5 via the Anthropic API) · **Status:** fixed

## What happened
In the `covered_marker` scenario (two sheet corners covered mid-session, the session pauses for
setup) the real model passed 1 of 3 runs. In the failing runs it spoke the right fix and then
ended its pause run without calling `recalibrate` and `request_resume`, so the patient stayed
paused with no prompt to carry on (the rule fallback still offered Resume). A first wording fix
made it call both in the same turn, so `request_resume` ran on the stale frame and was refused.

## Evidence
- Commit `234b86f` message and `docs/RISKS.md` (2026-10-21, "Re-check with a new API key").
- After the fix: `evaluation/results/agent_recheck_2026-10-21_covered_marker_x3.md` (3/3, `--repeat 3`) and `evaluation/results/agent_recheck_2026-10-21_all.md` (15/15 scenarios, 0 guardrail violations, first action p50 / p95 3738 / 6245 ms), regenerated by `evaluation/scripts/agent_eval.py --planner anthropic`.
- The failing runs themselves (1/3, and the intermediate wording) were not kept as results files; only the commit message and RISKS record them.

## Why
The pause job's instructions did not say the fix line is not the end of the job, nor that the
camera must be re-checked *after* the patient has had time to act.

## What we changed
`234b86f`: the system prompt and the pause job say: after the fix line, `recalibrate` alone,
wait, then `request_resume`; never both together, never stop after the fix line (policy
2026-10-21.1, tests in `services/session/tests/test_agent_plan_policy.py`).

## Status
Fixed: 3/3 on the scenario and 15/15 overall on synthetic frames. Not yet seen on a live session.
