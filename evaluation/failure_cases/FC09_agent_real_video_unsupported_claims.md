# FC09 — Agent claims on real video that motion capture does not support

**Source:** REHAB24-6 Ex1 real video (9 healthy adults, mocap lab) through the product pipeline and the agent; patient taps simulated · **Status:** open

## What happened
Of the claims the agent made in its set reviews, motion capture supported 67 of 83 on Claude
Sonnet 5.5 (×2 repeats) and 62 of 83 on Haiku 5.5; the rule coach alone, 36 of 79. Sonnet's 16
unsupported claims: hold 14, hike 1, short 1 (Haiku: hold 16, lean 4, hike 1). In one induced
pause (`induced-hips-PM_109`, hips cropped on purpose at 65.5 s) the agent did not name the fix:
it said "The camera sees you fine. Some reps missed because the hold was short…". This run
(12 Oct) predates the 25 Oct arm fix (FC01): the front view no longer needs the hips, so the same
crop would not cause that pause today (not re-run).

## Evidence
`evaluation/results/agent_video_v0.md` ("Headline", "Misses explained"), regenerated by
`evaluation/scripts/agent_video_eval.py`. Frames are REHAB24-6 (CC BY-NC 4.0) and are not copied
here.

## Why
The dataset is not our exercise: subjects lift overhead with no 3 s hold, so every scored set has
true faults and there are no clean sets. An unsupported claim is a fault named that mocap says is
absent or that a front view cannot measure. Most of Sonnet's are about the hold: the quoted
reviews mix the prescription's instruction ("hold for the full three seconds") with claims that
holds ended early on sets where mocap did not find that fault (our reading of the quotes in the
results file).

## What we changed
Nothing for this; the prompt was not tuned to this dataset (it would be fitting the agent to
someone else's exercise). The real-video run did find two other agent bugs, fixed 12 Oct
(the team's notes: pause re-trigger every 3 s, a lost spoken fix after a setup pause).

## Status
Open. Needs labelled clean and faulty sets of our own exercise (dataset v1). Stated as a caveat in
the results file.
