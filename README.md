# Praxis

An agentic vision coach for therapist-prescribed upper-limb rehab at home, using the laptop's built-in camera, two printed sheets and everyday objects. Team Praxis' entry in the **OpenCV AI Competition 2026 (powered by AWS)**.

> Praxis is an adherence and coaching aid. **It is not a medical device.** The therapist prescribes; the coach proposes within the prescription; hard-coded stop rules always win.

Built on **OpenCV 5.0.0** (`opencv-python-headless==5.0.0.93`, pinned). Video is processed in memory and never stored by default; only events, metrics and logs leave the device.

The locked exercise set (28 Sep 2026) is **three camera-coached exercises**: **Arm out to the side** (shoulder abduction, front view, pose model) and **Waiter – cup** (the printed 5-dot sheet) daily, and the **Nine-Hole Peg Test** as the weekly assessment. Pendulum, Arm to the front, Rotate out and Rotate in are **hidden**: their code, avatar clips and perception tests stay in the tree, dormant behind the registry's `visible` flag, but no screen shows them, nothing schedules them and the service refuses them. The default day is Arm out to the side → Waiter – cup (~10 min), at a dose set by the check-in pain: 0–3 full, 4–6 gentle, ≥ 7 rest + therapist flag. Design source of truth: `docs/wireframes/Praxis_HiFi_Wireframes_v1.1.pdf`. Build plan: `docs/PLAN.md`.

**For judges:** live on AWS (Graviton4 c8g + COOL OpenCV, HTTPS) at **https://dl8xykmg8ki61.cloudfront.net** · five-minute guide [`docs/JUDGE_QUICKSTART.md`](docs/JUDGE_QUICKSTART.md) · technical report [`docs/TECHNICAL_REPORT.md`](docs/TECHNICAL_REPORT.md) (problem, users, architecture, OpenCV 5, agent, AWS + COOL benchmark, evaluation, responsible use, limitations) · module-by-module detail [`docs/ENGINEERING_NOTES.md`](docs/ENGINEERING_NOTES.md).

**Accessibility:** [`docs/ACCESSIBILITY.md`](docs/ACCESSIBILITY.md) — WCAG 2.1 AA audit of every screen and dialog (axe-core in vitest and in headless Chrome, a keyboard-only critical path, live regions, reduced motion): what was fixed, the three contrast exceptions kept by decision, and what is still not served (the coach is caption-only since 10 Oct).

**Architecture:** [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — system diagram (browser → OpenCV 5 session service → stop rules → rule / agent coach → trace + SQLite; AWS EC2 + COOL + CloudFront live, S3 / CloudWatch / CDK dashed as planned; the agent runs on Claude via the Anthropic API, Bedrock is not used), the OpenCV 5 pipeline per exercise, and the agent's perception → decision → action loop with the patient's approval step.

## 60-second quickstart (edge / laptop mode)

```bash
# 0. Print the sheets at 100 % (A4 or US Letter). Check the scale bar measures 80 mm.
#    docs/sheets/nhpt_board.pdf · docs/sheets/cup_targets.pdf

# 1. Session service (Python 3.12 + uv). fetch_models downloads the Apache-2.0 OpenCV Zoo ONNX files (25 MB).
cd services/session && uv sync && uv run python tools/fetch_models.py && uv run uvicorn praxis_session.main:app --port 8000
#    → http://127.0.0.1:8000/health  {"status":"ok","opencv_version":"5.0.0","mode":"edge"}

# 2. Web app (pnpm). No sign-in: the app opens straight on Home (`/` redirects to `/details`).
cd web && pnpm install && pnpm dev
#    → http://localhost:5173/details  Home (affected areas) → Start session → Choose → Demonstration → check-in · /demo?exercise=cup&side=left shows the demonstration
#    → http://localhost:5173/setup?exercise=nhpt  (Vite picks the next port if 5173 is busy)
#    Click Allow on the camera prompt. Lay the printed NHPT sheet flat 25–35 cm in front of the
#    laptop and tilt the screen forward until the whole sheet shows (laptop camera only):
#    the checklist turns Pass and "Continue to demonstration" unlocks.
#    → http://localhost:5173/session?hand=left            runs the Nine-Hole Peg Test live.
#      Pegs are found by colour. Bright pegs on a white sheet work out of the box; for wooden
#      or pale pegs, or a coloured/wooden board, seat one peg and tap that hole in the Board view
#      ("Tap a seated peg to sample its colour") — the service samples a 6 mm patch and uses a
#      ±12° hue window from then on (WebSocket command {"cmd":"sample_colour","hole":k}), or press
#      "Pegs not found? Tap a peg on the picture" and tap a peg on the camera view.
#    → http://localhost:5173/session?exercise=cup&side=left runs Waiter – cup (blue band on the cup base, docs/sheets/cup_targets.pdf;
#      a different band colour: press "Cup not found? Tap the cup base on the picture" and tap it, or Enter
#      for the cup on its dot; sends {"cmd":"sample_colour","x_px":..,"y_px":..}. Black/grey/white is refused with the reason).
#    → http://localhost:5173/session?exercise=abduction&side=left runs Arm out to the side (face the camera,
#      no sheet needed). A link to a hidden exercise (pendulum, arm, external_rotation, ...) goes back to Choose.
#    → http://localhost:8000/api/plan?pain=5  today's plan at the gentle tier.
#
#    Socket form (ids in services/session/praxis_session/perception/exercises.py):
#    ws://localhost:8000/ws/session?mode=arm&exercise=abduction&tier=gentle&side=left

# 3. Replay mode (no webcam) — the judge fallback, identical pipeline
#    In the app: Settings → Demo and judging → "Replay a recorded session" → pick a clip.
#    A replayed session is saved as `source: replay`: listed with a Replay badge (Progress,
#    therapist view, report, Home), never counted in trends, practice totals, pain lists,
#    adherence or the NHPT trend.
#    From the CLI:
cd services/session
uv run python -m praxis_session.replay ../../evaluation/dataset_v0/synthetic_nhpt_01.mp4 --mode nhpt --quiet

# 4. Regenerate every evaluation number
uv run python ../../evaluation/scripts/make_dataset_v0.py && uv run python ../../evaluation/scripts/eval.py
uv run python ../../evaluation/scripts/latency.py --replay          # results/latency_v0.{md,json}
uv run python tools/fetch_rehab24.py                                 # REHAB24-6 arm abduction, ~0.55 GB, git-ignored, CC BY-NC (evaluation only)
uv run python ../../evaluation/scripts/rehab24_eval.py               # real video vs motion capture: results/rehab24_v0.{md,json}
uv run python ../../evaluation/scripts/rehab24_thresholds.py         # hike allowance + front-gate fit/held-out: results/rehab24_thresholds_v0.{md,json}
uv run python ../../evaluation/blender/make_dataset_3d.py            # 3-D Blender renders of NHPT + Waiter – cup (~35 min, Blender 5.2; clips git-ignored)
uv run python ../../evaluation/scripts/eval_3d.py                    # synthetic 3-D results: results/synthetic3d_v0.{md,json} (--use-cache: no clips needed)

# 5. Real recordings (step by step for the whole team: evaluation/PROTOCOL.md)
uv run python tools/record_session.py record                         # consented clip, git-ignored, 30-day deletion
uv run python tools/label_clip.py <clip.mp4> --labeller <initials>   # keyboard labeller
uv run python tools/dataset_v1.py manifest                           # labelled clips -> manifest
uv run python ../../evaluation/scripts/eval.py --dataset ../../evaluation/dataset_v1
```

## One-container deploy (Railway / any Docker host)

The image builds the web app and serves it from the session service, so the browser talks to **one origin** for the page, `/api`, `/health`, `/events` and the WebSocket (`/ws/session`). Build context is the repo root; models are fetched (SHA256-pinned) at build time; the SQLite store lives in `/app/data` (ephemeral unless a volume is mounted). `PORT` is honoured; `railway.json` points Railway at the Dockerfile and the `/health` check.

**Team test (review build only).** With `PRAXIS_TEAM_TEST=1` the app asks each browser once "Who's testing?" (a name, no password) and saves every session under it. `GET /api/review?format=md` (also Settings › Demo and judging › Team test report) lists, per exercise and tester, verified/unverified reps and why, tracking losses and which marker or body part went missing, stop rules that fired, coach corrections and the screen-08 answers, with the most widespread problems first (`praxis_session/review.py`). With the agent on (`PRAXIS_AGENT=anthropic`) an "AI coach" section reads each session's trace: runs and outcomes, triggers, tools called and failed (a guardrail refusal, e.g. a stale run or a dose already in force, is listed apart from a failure), MCP vs direct transport, errors (the rule coach takes over), dropped output, checkpoint → first action time, tokens and an estimated cost. Live sessions only; replays and the sample history are not counted. A session is stored only when its feedback arrives, so the review also counts live sockets that closed before that (close code, agent run in flight, seconds since the last agent run; trace row `socket_close`). On Railway the store sits on a volume at `/app/data`, so it survives redeploys; the service runs in US East (`us-east4-eqdc4a`, moved from Amsterdam on 13 Oct to cut live-frame lag). The flag is off by default and on the judge build.

**Therapist-only writes (21 Oct).** There is no sign-in (Cognito is deferred), so the two therapist actions, Edit practice days (`PUT /api/prescription/schedule`) and Mark reviewed (`POST /api/flags/{id}/reviewed`), are guarded by `PRAXIS_THERAPIST_TOKEN`: with it set, only a request carrying `X-Praxis-Therapist-Token: <token>` writes; unset (the default), only a local request with no proxy headers writes (your laptop), and every request through Railway, CloudFront or the EC2 proxy gets 403, which the therapist screen shows as "Therapist only … Nothing was changed". To edit from a browser on a hosted build, set the token on the server and, in that browser's console, `localStorage.setItem('praxis.therapistToken', '<token>')`. `/health` says which rule is active (`therapist_writes: token | local_only`). Reads and the patient's own writes (check-in, goal log, self-report, feedback edit) stay open.

```bash
docker build -f services/session/Dockerfile -t praxis .
docker run -p 8000:8000 praxis            # → http://127.0.0.1:8000/
```

Locally you can serve a build the same way without Docker: `cd web && pnpm build`, then start uvicorn with `PRAXIS_WEB_DIST=../../web/dist`. This is still the **edge build** (`PRAXIS_CLOUD_ENABLED=0`, rule-based coach); hosting it remotely means webcam frames travel to the host over TLS, where they are processed in memory and discarded, never stored. The AWS cloud mode is separate: Graviton4 c8g + COOL OpenCV behind CloudFront HTTPS (`infra/ec2/`, `docs/ENGINEERING_NOTES.md` §5).
