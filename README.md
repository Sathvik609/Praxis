# Praxis

An agentic vision coach for therapist-prescribed upper-limb rehab at home, using one ordinary webcam, two printed sheets and everyday objects. Team Praxis' entry in the **OpenCV AI Competition 2026 (powered by AWS)**.

> Praxis is an adherence and coaching aid. **It is not a medical device.** The therapist prescribes; the coach proposes within the prescription; hard-coded stop rules always win.

Built on **OpenCV 5.0.0** (`opencv-python-headless==5.0.0.93`, pinned). Video is processed in memory and never stored by default; only events, metrics and logs leave the device.

The locked exercise set (28 Sep 2026) is **three camera-coached exercises**: **Arm out to the side** (shoulder abduction, front view, pose model) and **Waiter – cup** (the printed 5-dot sheet) daily, and the **Nine-Hole Peg Test** as the weekly assessment. Pendulum, Arm to the front, Rotate out and Rotate in are **hidden**: their code, avatar clips and perception tests stay in the tree, dormant behind the registry's `visible` flag, but no screen shows them, nothing schedules them and the service refuses them. The default day is Arm out to the side → Waiter – cup (~10 min), at a dose set by the check-in pain: 0–3 full, 4–6 gentle, ≥ 7 rest + therapist flag. Design source of truth: `docs/wireframes/Praxis_HiFi_Wireframes_v1.1.pdf`. Build plan: `docs/PLAN.md`.

**Architecture:** [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — system diagram (browser → OpenCV 5 session service → stop rules → rule / agent coach → trace + SQLite; AWS boxes dashed as planned for W6), the OpenCV 5 pipeline per exercise, and the agent's perception → decision → action loop with the patient's approval step.

## 60-second quickstart (edge / laptop mode)

```bash
# 0. Print the sheets at 100 % (A4). Check a marker measures 40 mm with a ruler.
#    docs/sheets/nhpt_board.pdf · docs/sheets/cup_targets.pdf

# 1. Session service (Python 3.12 + uv). fetch_models downloads the Apache-2.0 OpenCV Zoo ONNX files (25 MB).
cd services/session && uv sync && uv run python tools/fetch_models.py && uv run uvicorn praxis_session.main:app --port 8000
#    → http://127.0.0.1:8000/health  {"status":"ok","opencv_version":"5.0.0","mode":"edge"}

# 2. Web app (pnpm). No sign-in: the app opens straight on Home (`/` redirects to `/details`).
cd web && pnpm install && pnpm dev
#    → http://localhost:5173/details  Home (affected areas) → Start session → Choose → Demonstration → check-in · /demo?exercise=cup&side=left shows the demonstration
#    → http://localhost:5173/setup?exercise=nhpt  (Vite picks the next port if 5173 is busy)
#    Click Allow on the camera prompt, hold the printed NHPT sheet in view:
#    the checklist turns Pass and "Continue to demonstration" unlocks.
#    → http://localhost:5173/session?hand=left            runs the Nine-Hole Peg Test live.
#      Pegs are found by colour. Bright pegs on a white sheet work out of the box; for wooden
#      or pale pegs, or a coloured/wooden board, seat one peg and tap that hole in the Board view
#      ("Tap a seated peg to sample its colour") — the service samples a 6 mm patch and uses a
#      ±12° hue window from then on (WebSocket command {"cmd":"sample_colour","hole":k}).
#    → http://localhost:5173/session?exercise=cup&side=left runs Waiter – cup (blue band on the cup base, docs/sheets/cup_targets.pdf;
#      a different band colour: send {"cmd":"sample_colour","x_mm":..,"y_mm":..} at the cup base, no UI yet).
#    → http://localhost:5173/session?exercise=abduction&side=left runs Arm out to the side (face the camera,
#      no sheet needed). A link to a hidden exercise (pendulum, arm, external_rotation, ...) goes back to Choose.
#    → http://localhost:8000/api/plan?pain=5  today's plan at the gentle tier.
#
#    Socket form (ids in services/session/praxis_session/perception/exercises.py):
#    ws://localhost:8000/ws/session?mode=arm&exercise=abduction&tier=gentle&side=left

# 3. Replay mode (no webcam) — the judge fallback, identical pipeline
#    In the app: Settings → Demo and judging → "Replay a recorded session" → pick a clip.
#    A replayed session is saved as `source: replay`: listed with a Replay badge (Progress,
#    therapist view, report, Home), never counted in trends, practice totals, pain lists,
#    adherence or the NHPT trend.
#    From the CLI:
cd services/session
uv run python -m praxis_session.replay ../../evaluation/dataset_v0/synthetic_nhpt_01.mp4 --mode nhpt --quiet

# 4. Regenerate every evaluation number
uv run python ../../evaluation/scripts/make_dataset_v0.py && uv run python ../../evaluation/scripts/eval.py
```

Tests: `uv run pytest -q` and `uv run ruff check .` (session) · `pnpm test && pnpm typecheck && pnpm lint` (web).

## Agent coach (Claude + OpenCV tools over MCP, optional)

Off by default (`PRAXIS_AGENT=off`: rule coach only, exactly as before). With it on, Claude Sonnet 5 (Strands Agents) runs at checkpoints — check-in, end of a set/arc, a stop-rule pause after unverified reps or lost tracking, peg-test end, session end — and calls OpenCV 5 tools served by FastMCP at `/mcp/perception`, `/mcp/exertion`, `/mcp/coach` (streamable HTTP, same port). Every dose change and every resume is a prompt the patient accepts; stop rules still run first. Details and the workflow diagram: `docs/AGENT.md`.

```bash
cd services/session
cp .env.example .env              # set ANTHROPIC_API_KEY and PRAXIS_AGENT=anthropic (.env is git-ignored)
uv run uvicorn praxis_session.main:app --port 8000 --env-file .env
curl -s localhost:8000/health     # "agent": {"mode": "anthropic", "model": "claude-sonnet-5", "mcp": true, "ready": true}
PRAXIS_AGENT=scripted uv run uvicorn praxis_session.main:app --port 8000   # no key: canned tool calls, for UI work
uv run python ../../evaluation/scripts/agent_eval.py --planner scripted    # nine scenarios, free (CI)
uv run python ../../evaluation/scripts/agent_eval.py --planner anthropic --yes   # real model, prints the cost first
```

Status 10 Oct: run against real Claude (Sonnet 5 via the Anthropic API, dev): 9/9 scenarios on four consecutive full runs, 0 guardrail violations, ~$0.39 per run (`evaluation/results/agent_v0_anthropic.md`, traces in `traces/agent/anthropic/`). Bedrock not run yet. Keep `PRAXIS_AGENT=off` on the public Railway site until a spend limit exists (`docs/RISKS.md`). Bedrock: `PRAXIS_AGENT=bedrock`, `PRAXIS_BEDROCK_MODEL_ID`, `AWS_REGION`, and `PRAXIS_CLOUD_ENABLED=1`.

## One-container deploy (Railway / any Docker host)

The image builds the web app and serves it from the session service, so the browser talks to **one origin** for the page, `/api`, `/health`, `/events` and the WebSocket (`/ws/session`). Build context is the repo root; models are fetched (SHA256-pinned) at build time; the SQLite store lives in `/app/data` (ephemeral unless a volume is mounted). `PORT` is honoured; `railway.json` points Railway at the Dockerfile and the `/health` check.

```bash
docker build -f services/session/Dockerfile -t praxis .
docker run -p 8000:8000 praxis            # → http://127.0.0.1:8000/
```

Locally you can serve a build the same way without Docker: `cd web && pnpm build`, then start uvicorn with `PRAXIS_WEB_DIST=../../web/dist`. This is still the **edge build** (`PRAXIS_CLOUD_ENABLED=0`, rule-based coach); hosting it remotely means webcam frames travel to the host over TLS, where they are processed in memory and discarded, never stored. The AWS/COOL cloud mode in `CLAUDE.md` §4 is separate and deferred to W6.

## Static design preview (for designers; not the product)

`cd web && pnpm build:design` (optionally `--outDir <dir>`) builds a click-through copy of the app into `web/dist-design/` that needs **no service and no camera**: relative asset URLs, hash routing, unminified output. Only `--mode design` includes `src/designPreview/`; `pnpm build` is unchanged. Every screen reads fixtures captured from the live service (`node scripts/capture-design-fixtures.mjs`); sessions replay recorded event streams (NHPT and Waiter – cup: the synthetic replay clips recorded over the service's WebSocket; Arm out to the side and Camera setup: the service's pipeline run offline on synthetic input, `uv run python ../../web/scripts/record-design-streams.py` from `services/session`). The camera shows a labelled placeholder and every page carries a "Design preview · sample data · no camera" tab. Nothing is measured or stored; writes (flag reviewed, schedule edit, check-in) live in page memory until reload.

**6 Oct, design v2 camera setup (Task 16):** camera setup is the designers' full-screen layout — Exit, the exercise and "Camera setup · Left arm", an Audio on/off switch that reads the coach pill aloud, the camera with its guide frame and a pill that says "Live · not recording · Mirrored" and where the video is processed, an `i` guide (placement diagram, tips, the checklist, Restart camera, Change exercise), a coach pill with the next thing to fix, and a row of step icons. The checks are the service's `setup_checks`; pose rows it does not measure yet and, for the sheet tasks, "Is this your left arm?" are confirmed by the patient in the pill. When everything passes: a 2 s still-pose count (reset by the service's steadiness check on the sheet tasks; time only for the arm setup, which has no steadiness event), then a 4 s auto-continue into the session with a visible Cancel.

**6 Oct, design v2 feedback (Task 18):** after a session the feedback form asks one question per step, as the designers drew it: pain right now (0–10 with decorative faces, today's check-in pain and the change beside it), how hard it was (Too easy · Just right · Hard · I couldn't finish, each with the effort number it stands for), whether it could be done again tomorrow, and — only when the session ended early — what got in the way. The last step keeps an optional note for the therapist. Pain at or above the prescription's stop level says "Your therapist will be flagged.", the same rule the service uses to write the flag. Skipped questions are not recorded, never zero; Edit feedback on the report reopens the same form.
